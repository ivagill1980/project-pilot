Project Pilot

把超大型软件项目变成一个始终可定位、可验证、可恢复的闭环控制系统。它不会只告诉你“下一步做什么”，而是让你在做每一步时始终知道：最终目标是什么、现在在整个计划的哪里、完成了多少、为什么现在做这件事。

核心原则：One Thing in Context.
核心模型每轮导航 HUD三种模式Rescue命令状态文件对话演示使用方式

1. 它不是 TODO 工具，而是项目控制层

Project Pilot 持续比较“目标状态”和“项目现实”，然后决定下一步。计划不是事实；代码、测试、CI、运行结果和最新决策共同构成现实。

01

保持方向

最终目标、Phase、Milestone、Task、Step 始终形成完整坐标。

02

控制漂移

发现计划、文档、架构、范围、验证体系与实际代码的偏离。

03

随时恢复

中断后不是读完整聊天历史，而是从项目状态和 checkpoint 重建“YOU ARE HERE”。

2. 每一轮都显示全局 + 当前

“专注”不等于把整个地图藏起来。默认只执行一个动作，但持续显示它在整个项目中的位置和贡献。

3. NORMAL / RECONCILE / RESCUE

Skill 不要求从项目第一天开始使用。任何已有项目都可以接入；状态越混乱，越倾向从 Rescue 开始。

NORMAL正常推进地图可信、验证健康，继续小步交付。
RECONCILE轻度偏航计划与现实出现差异，校准而不推翻基线。
RESCUE严重失控先考古、重建现实，再重新基线和稳定。

4. Rescue：随时加入一个已经混乱的项目

Rescue 的第一原则：刚进入项目时不要冲动重构。先只读调查，把“文档声称什么”和“代码/测试证明什么”分开。

6. Skill 用什么保持“项目记忆”

聊天不是唯一事实源。Project Pilot 把导航状态持久化，让新 session 可以从文件恢复，而不是依赖模型记住之前全部对话。

推荐控制目录

.project-pilot/ ├── STATE.md # 当前坐标和下一动作 ├── MAP.md # 全项目层级与进度 ├── HEALTH.md # CI / 测试 / 漂移 / 风险 ├── RECOVERY.md # Rescue 过程与返回目标 ├── PARKING_LOT.md # 支线想法 ├── DECISIONS.md # 关键决策索引 ├── SESSION_LOG.md ├── plans/ │ ├── active/ │ ├── completed/ │ └── abandoned/ └── snapshots/

状态不是文档堆

AGENTS.md：稳定规则与地图入口，不放大量临时状态。

Reference docs：架构、产品、约定等长期知识。

Checkpoint / STATE：当前 session 可恢复状态。

Tests / hooks / scripts：把可确定的验收从语言模型转移给机器执行。

8. 如何使用

`SKILL.md` 是完整工作流定义。把它安装为 Codex/兼容 Agent Skills 的 Skill 后，在目标仓库中通过自然语言调用即可。大型已有项目建议第一次直接说“接管这个项目并校准真实状态”。

安装 Skill

使用本页配套的 SKILL.md。Skill 格式遵循 Agent Skills / OpenAI Skills 的 Markdown 工作流模式。

第一次进入仓库

Skill 会先判断 BUILD、RECONCILE 还是 RESCUE；已有复杂项目通常先做轻量 archaeology。

建立项目地图

Project → Phase → Milestone → Task → Step。全局地图稳定，当前附近才做细规划。

进入闭环

Select → Act → Verify → Record → Navigate。每次小步都有机器可观察的完成门。

发现失控

先 Reconcile；严重时自动建议 Rescue → Rebaseline，而不是继续在错误计划上堆 patch。

最简单的首次指令：
接管这个项目。先不要改代码，重建真实项目地图，告诉我整体完成情况、当前位置、主要漂移和最合理的下一步。
